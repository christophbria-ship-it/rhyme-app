# Rhymer — rhyming dictionary
Perfect, near, slant and multi-syllable rhymes for 251,317 words (125,938 CMUdict + 20,876 rule-derived inflections + 104,503 g2p_en-generated), with syllable / part-of-speech / popularity / length filters.
Data: CMU Pronouncing Dictionary, wordfreq 'large' English list + zipf frequencies, g2p_en (neural grapheme-to-phoneme), WordNet 3.0 (POS; inflected forms mapped to base forms).
Generated pronunciations are lower confidence (`conf`: dict > derived > g2p), ranked after dictionary words, and shown in italics.
`prepare_words.py` (needs `pip install wordfreq g2p_en`) regenerates `data/extra_words.tsv` and `data/zipf.tsv`; set `TARGET` for vocabulary size.

## Rhyme tiers
- **perfect**: identical sounds from the last stressed vowel; `matched_syllables` counts how far the match extends (multi-syllable).
- **near**: same vowels, consonants in the same family (voicing/manner), e.g. month → once.
- **slant**: same stressed vowel sequence with consonant similarity score ≥ 0.6 (last consonant per syllable: same=1, family=0.8, manner=0.6), or exact consonant skeleton (≥2 consonants). Unstressed-only tails are excluded.

## Run (server)
    python3 -m venv .venv && . .venv/bin/activate
    python build_index.py          # -> data/index.pkl
    WORKERS=4 python server.py 8765  # pre-fork workers, http://localhost:8765
API: `/api/rhymes?word=&syllables=1,2&pos=n,v,adj,adv&min_len=&max_len=&min_freq=&sort=score|freq|alpha|length&limit=`, `/api/suggest?q=`, `/api/health`

## Static build (GitHub Pages)
`python build_static.py` → `site/` (UI + 4 JSON data shards + in-browser engine `api-shim.js`, parity-tested against the Python engine).
`.github/workflows/pages.yml` builds and deploys it on push to `main` (Settings → Pages → Source: GitHub Actions).

## Installable app (PWA)
The static site ships `manifest.webmanifest`, icons (`static/icons/`, regenerate with `python tools/make_icons.py`), iOS meta tags and `sw.js`.
The service worker precaches the app shell + all data shards (works offline); its cache name is a content hash set by `build_static.py`, so each deploy installs a fresh cache and deletes the old one.

## Songwriting tools
- **Themed rhymes toggle**: pick one of 20 themes (love, heartbreak, night, ocean, city, …). On-theme rhymes are marked ✦ and listed first; "On-theme only" filters to them. Theme word sets (`data/themes.json`) are generated by `build_themes.py` from curated seed words expanded through full WordNet 3.0 (synonyms, hyponyms, meronyms, derivations, gloss words) plus inflections. API: `/api/themes`, `/api/rhymes?...&theme=love&theme_only=1`.
- **Line helper**: give the line to rhyme with and the start of your next line; it shows per-word syllables and stress (● stressed, ○ unstressed) and suggests endings that rhyme *and* bring your line to the same syllable count (falls back to any length). API: `/api/line?prev=&line=&theme=`.
- **Lyrics pad**: a notebook-style editor with live per-line syllable counts, rhyme-scheme letters (solid = perfect/repeat, dashed = near rhyme; letters restart each stanza), autosave to localStorage, copy/download/clear, and click-an-end-word to look up rhymes. API: `GET /api/analyze?text=` or `POST /api/analyze {"text": ...}`.
All three work in the static/offline PWA build too (same logic ported to `api-shim.js`, parity-tested).

## Related rhymes (v4)

The default theme mode is now **"Related to my word"**. A search for *snow* brings up words that are both associated with it and rhyme with it (low, below, slow, flow, blow, cold…), along with short phrases that end in a rhyme. The 20 mood themes are still in the same picker.

- Data: GloVe 6B 100d (wiki+gigaword) vectors, limited to the top 45k frequent words. That leaves 39,691 usable words. Each word keeps 36 rhyme-neighbours, ranked by cosine similarity × rhyme quality (perfect 1, near .85, slant .7, assonant .5), and 20 general neighbours used for phrases.
- Built by `build_assoc.py` (needs gensim plus the GloVe model) into `data/assoc/`: `vocab.json` and 16 binary shards of uint16 ids plus uint8 sims. About 6.1 MB total. The static site loads only the shard it needs, on demand.
- API: `GET /api/related?word=snow`, `GET /api/rhymes?word=snow&theme=related`.

## AI line writer (Cloudflare Worker)

`worker/` holds a Cloudflare Worker (`rhymer-ai`) that uses Workers AI (`@cf/meta/llama-3.1-8b-instruct-fp8`). You give it a lyric line and it returns 5–8 next lines that loosely rhyme. The app re-ranks them with the local rhyme engine (`POST /api/rank_lines`) so the true rhymes come first. The worker restricts CORS to the Pages origin, rate-limits each IP (12/min, 300/day per isolate), caps input lengths, and keeps no secrets on the client.

Deploy:

```
cd worker && npx wrangler deploy      # needs CLOUDFLARE_API_TOKEN (Workers Scripts:Edit, Workers AI) + account
echo "https://rhymer-ai.<subdomain>.workers.dev" > URL   # build_static.py writes it into site/config.js
```

Until the worker URL is configured, or whenever the worker or the network is down, the "✨ AI" buttons fall back to offline rhyme suggestions. The Python server can proxy `/api/ai/lines` when `RHYMER_AI_URL` / `RHYMER_AI_KEY` are set. Worker tests: `cd worker && node --test test/`.
